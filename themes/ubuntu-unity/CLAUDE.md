# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Hugo theme that styles a personal site as the Ubuntu 14.04 Unity desktop: top panel, vertical launcher dock, a single "window" containing the page content, and a trash icon. Everything is server-rendered by Hugo partials and styled by `assets/css/main.scss`; small TypeScript modules under `assets/js/` enhance the SSR DOM (dropdown toggling, drag, clock tick, dialog stack, etc.). The TS compiles through Hugo Pipes (`resources.Get | js.Build | resources.Fingerprint`) at site-build time, called from `baseof.html` and `head.html` — there is no separate build step inside this directory.

## Anatomy

- `assets/css/main.scss` (~3000 lines) — every Unity-styled selector lives here, all prefixed `up-` (Ubuntu/Unity). One file by design; do not split it.
- `assets/js/app.ts` — entry point. Calls `initDialogs`, `initNotify`, `initLock`, `initTopPanel`, `initTrash`, `initDaw`, `initDash`, `initHud`, `installPageWindow`, then tags `<body>` with `up-ready`. `initLock` runs before `initTopPanel` so the lock overlay's window `keydown` listener is registered first and can `stopImmediatePropagation` past the dropdown-close handler when Esc unlocks; `initNotify` also precedes it so the panel's first bubble (volume scroll, hotspot toggle) finds the daemon ready.
- `assets/js/blog.ts` — IIFE module. Drives the post list's filter/sort/search and the focused single-post reader. Manipulates server-rendered DOM directly (`data-up-post-row`, `data-up-search-*`, etc.).
- `assets/js/projects.ts` — IIFE module. Owns the `/projects/` page's Places/Languages sidebar filtering and search, and builds the right-pane preview (single or multi-select summary) entirely client-side from each tile's `data-*` attributes. The selection model comes from `desktop-select.ts` (this page contributes the preview painting via `onRender`); all grid pointer gestures are delegated to `projects-desktop.ts` with the default hooks. Gated on `[data-projects-kind]` so it no-ops everywhere else.
- `assets/js/desktop-select.ts` — the shared icon-grid selection model (`createSelection`): a `Set` of selected tiles plus an anchor, with the generic `.is-active`/`.is-anchor`/`.is-focused` class toggling, mirrored into `aria-pressed` on `<button>` tiles so AT hears selection state. `projects.ts` and `trash.ts` each create an instance and supply an `onRender` that paints their own pane (preview / footer count). The `selectable` predicate defaults to attached, visible tiles, so `syncAfterChange()` prunes both filter-hidden (projects) and removed (trash) tiles.
- `assets/js/projects-desktop.ts` — the shared desktop file-manager gesture engine over an icon grid: click-select, drag-to-reorder (the selected tiles lift and ride the cursor as one rigid block while the others FLIP into their new cells; DOM order is display order, mutating the shared `tiles` array in place), double-click, Ctrl/Shift multi-select, rubber-band marquee, and a right-click context menu. Keyboard activation (click with `detail===0`) selects and opens like Nautilus; Shift+F10/Menu opens the context menu as a `role=menu` of focusable `menuitem` rows (arrows wrap, Home/End, Enter/Space activate, Tab closes) and restores focus to the tile when the menu was keyboard-opened. Generalized over optional `DesktopDeps` hooks — `tileSelector`, `emptyAnchor`, `onOpen`, `tileMenu`/`emptyMenu`, `reduceMotion` — whose defaults are the projects behaviors (open `data-url` on GitHub, Open/Copy menu); the trash window overrides them. Returns a `DesktopController` with `removeTiles` (session-only removal: splices both the shared `tiles` array and the captured original order, detaches, FLIPs survivors) and `cleanUpIcons` (restores original order; filters by `isConnected` so removed tiles are never resurrected). Pure Pointer Events; no localStorage; all state is per-install closure state — never add module-level mutable state (see Editing notes on cross-bundle duplication).
- `assets/js/dialogs.ts` — clones `<template id="up-dialog-template">` once per `window.uiDialog(opts)` call, fills slots, stacks modal dialogs, handles Esc/Enter (Enter yields to the focused control's native activation and only confirms the primary when focus is elsewhere), contains Tab within the top dialog, restores focus to the opener on dismiss, handles backdrop-shake, and titlebar drag via CSS custom properties `--ox` / `--oy` so the shake keyframe respects per-dialog drag offset. `opts.render(content)` is an optional hook: it mounts a `.up-dlg-custom` container in the content column (after body/details, before the footer) for rich dialogs like Preferences to build live controls.
- `assets/js/prefs.ts` — session-only preferences (no persistence; reduce-motion seeds from the OS prefers-reduced-motion query at startup in app.ts and accent defaults to orange, both reset on reload). `setReduceMotion` toggles the `body.up-reduce-motion` class (neutralizes all animation/transition); `setAccent` swaps all four accent shades (`--orange`/`--orange-light`/`--orange-dark`/`--orange-darker`) on `:root` from a small Ubuntu palette so accent gradients recolor on both stops; `showPreferences` opens the settings dialog via the `render` hook. Imported by `top-panel.ts` (`dlg:prefs`, `dlg:power-saver`).
- `assets/js/shortcuts.ts` — the Help menu's "Keyboard shortcuts" dialog. A static `SECTIONS` table (Desktop / Dash & HUD / Blog & Projects / Terminal) rendered as native keycap-chip rows (`.up-kbd`; mouse gestures get the flat `is-gesture` pill) through the dialog `render` hook, mirroring `prefs.ts`. Purely presentational: every row documents a binding implemented elsewhere (`dialogs.ts`, `drag.ts`, `hud.ts` for the Alt tap, `top-panel.ts` for the sound indicator's scroll wheel, `page-window.ts`, `filter-nav.ts`, `projects-desktop.ts`, `shell/readline.ts`, `shell/terminal.ts` for the Shift+Tab focus escape screenReaderMode enables) — keep the table in sync when bindings change. Imported by `top-panel.ts` (`dlg:shortcuts`).
- `assets/js/midi.ts` — minimal Standard MIDI File parser. `parseMidi(ArrayBuffer)` walks the chunks (format 0/1), resolving running status, VLQ delta-times, note on/off pairs and the tempo metas into a flat, start-sorted `MidiNote[]` (channel, pitch, beat-based start/dur, normalized note-on velocity, plus an optional `dead` flag the Studio's right-click mute sets) plus bpm and total length. No controllers/pitch-bend. The reported bpm is the *dominant* tempo (the one active for the most beats), and multi-tempo files are honored by **warping**: every note's raw beat position runs through the file's tempo map into real seconds and back into dominant-tempo-equivalent beats, so the single-tempo player in `audio.ts` reproduces the original pacing exactly (rubato, count-ins, section changes) while everything downstream keeps thinking in plain beats — warped sections simply land between the nominal grid lines. The SMF default of 120 BPM applies before the first set_tempo. Covered by `midi.test.ts` (synthetic SMF fixtures; runs under `npm test` alongside the shell suites). Consumed only by `audio.ts`.
- `assets/js/audio.ts` — Web Audio MIDI player/synth engine behind the volume dropdown's play control and the Studio window. It plays a **playlist** of bundled MIDIs (`assets/midi/*.midi` — a rickroll cover, plus two more left unnamed on purpose), but takes any MIDI. Self-contained and session-only (no persistence, no window globals), mirroring `prefs.ts`. `configure(urls)` hands it the playlist (the URL array comes from Hugo's `resources.Get` via the panel's `data-vol-playlist` JSON attribute, so the player holds no song-specific data); `selectTrack(i)` switches entries (wraps; playback state carries over — a playing player restarts on the new song — while the per-song mixer strips and BPM override reset and the synth/FX params persist); `trackIndex()`/`trackCount()` report the selection and `trackName()` returns only the anonymous "Track N" — which song is which is deliberately a surprise. Parsed songs are cached per URL, and a stale fetch resolve can't clobber the active song. On the first play click it lazily creates the `AudioContext` (so the user gesture satisfies autoplay policy), fetches and parses the file, and streams it: a `setInterval` lookahead schedules every channel's notes ~0.2s ahead of the audio clock, looping at the end. Sixteenth-grid quantization is **adaptive per song** (`computeQuantize`): files whose onsets live on the grid get the tidy-up, files that don't (triplet writing, tempo-warped sections, fine sequencing) play untouched — snapping those is what "badly quantized" sounds like; swing's off-eighth test is a tolerance window so it works either way. Pitched notes are voiced additively from plain `sine` oscillators (built-in `square`/`triangle` types are silent in some Firefox builds), bass preset down low and melody preset higher; GM drum channel 9 is a synth kick / noise snare / noise hat. Everything musical is live-tweakable for `daw.ts`, read at schedule time so edits land within the lookahead: `getParams()`/`setParam` (the global "auto" melody voice — any concrete patch, not just the `WAVES` tables — attack, release scale, octave shift, unison detune — every partial doubled into a ±cents pair — vibrato depth into one shared 5.5Hz LFO that fans into every oscillator's `detune`, master lowpass cutoff, tanh drive and bit-staircase crush `WaveShaper`s — null curve = bypass — echo send + musical division, convolver-reverb send over a generated impulse, pitch-keyed stereo width via per-note `StereoPanner`s, eighth-note swing, humanize jitter/wobble, and velocity sensitivity — the one default that isn't neutral, 0.5, because the files' dynamics simply sound better honored), `strip(key)`/`noteStripKey(note)` (live per-strip `{gain, muted, solo, patch}` the scheduler consults — any solo silences non-soloed strips; `patch` is the strip's instrument from the `PATCHES` list: `"auto"` keeps the legacy pitch-split (bass voice below C3, the global wave-table voice above) while the rest pin the whole strip to one engine — the four additive tables, a band-limited 25%-duty `PeriodicWave` pulse, two 2-op FM voices (e-piano ratio 2, bell ratio 3.51 ringing past the note), an exponential-decay pluck with a noise tick, and a slow-attack detuned pad; the key is normally the MIDI channel, but when a song's pitched material all lives on one channel the bass register below `BASS_MAX_PITCH` gets a strip of its own, so solo-piano MIDIs mix as the two voices you actually hear; each note's key is frozen in a `WeakMap` on first sight so live transposition never re-routes a note to a different strip than the one it displays under), and `setBpm` (clamped override that reanchors `loopBase` mid-loop so the playhead doesn't jump). The mix runs master gain → lowpass → drive → crush → dry + two post-everything sends (tempo-synced feedback delay at the selected division, convolver reverb) → `DynamicsCompressor` → destination. `getSong()` exposes the parsed (live, mutable — the Studio transposes notes in place) `MidiSong`; `positionBeats()` is the playhead (the resume point while paused); `auditionNote(pitch, channel)` one-shots a preview through the chain; `seek(beats)` jumps the transport (mid-playback it cuts every voice — scheduled lookahead included — and re-anchors the loop; paused it just moves the resume point); `stop()` is the hard transport stop that rewinds to 0, while `toggle()` is pause/resume (`pausedAt` carries the position across the gap); `onChange(cb)` is the pub/sub that keeps the panel's and the Studio's transports agreeing (play/stop/seek/param/bpm changes all emit). `toggle()` resolves to the real playing state (false if the context stays suspended or the MIDI fails to load); `trackName()`/`isPlaying()` report state; `setVolume`/`setMuted` drive the master gain live (perceptual, capped low). Imported by `top-panel.ts` (`vol-play`/`vol-toggle`/slider + `configure`) and `daw.ts` (everything else).
- `assets/js/lock.ts` — the lock screen. `initLock` caches the SSR `[data-up-lock]` refs (no-op if absent); `showLock` reveals the overlay, ticks the clock each second, focuses the input, and traps Esc. Unlock (form submit or Esc) hides the overlay, stops the tick, and refocuses the page; the fade-out honors reduce-motion. Imported by `top-panel.ts` (`dlg:lock`).
- `assets/js/dash.ts` — the Unity Dash, the search overlay behind the launcher's BFB (the Dash button, `[data-dash-open]`) and a plain Super tap (a chord cancels the tap, so Cmd/Super shortcuts are untouched; some WMs swallow Super — the BFB is the universal path). Everything searchable is SSR'd by `_partials/dash.html` as category sections of tiles (apps with launcher icons, posts, projects with the shared folder-emblem partial, the playlist as anonymous "Track N" buttons); `initDash` only filters (every query token a substring of label+`data-keywords`), caps (`data-dash-cap` sections collapse behind a Unity "See N more results" expander; a lens-focused section is never capped), and dispatches. Page/post/project tiles are real `<a>`; app tiles carry `data-dash-action` — `studio`/`trash` call `openStudio`/`openTrash`, `music:<i>` selects the track and starts the transport inside the click gesture before opening the Studio, and the rest re-enter `top-panel.ts`'s exported `dispatchAction` as `dlg:<key>` so the Dash and panel run identical flows. Interaction is GNOME-style real focus, not aria-activedescendant: the input holds focus, arrows walk visible tiles geometrically (nearest row, closest horizontal center — works across sections without knowing the column count), tiles are `tabindex="-1"` so Tab stays structural (input → visible expanders → lens bar, wrapped), typing anywhere refocuses the input, Enter in the input opens the best match (title startsWith > includes > keyword-only, in DOM order), and Esc clears the query first, then closes — exactly like Unity. The lens bar re-filters to one category. Open/close mirrors lock.ts (hidden + `is-visible`, transitionend/timeout race, reduce-motion skips the wait; scroll/focus resets happen after un-hiding because writes are ignored under `display:none`); the Super-tap detector is suppressed while the lock screen or a dialog is up, and the BFB shows `.is-open` (never `.is-active`/`.is-focused` — those are page-window contracts on launcher tiles). Session-only: query, lens, and expansion state reset every open.
- `assets/js/hud.ts` — the Unity HUD, the type-to-search-the-menus overlay behind a plain Alt tap (chords cancel, mirroring the Dash's Super-tap detector; the keyup is `preventDefault`ed so Firefox's menubar stays put). `initHud` no-ops without `[data-up-hud]`. The index is rebuilt on every open by crawling the SSR'd top panel: every enabled `button[data-action]` / `a.up-dropdown-btn[href]` inside a `[data-dropdown-for]` (menu path = the menubar trigger's text or the indicator's aria-label; icon-only controls drop out via their empty labels), plus the not-currently-connected `button[data-net-name]` rows as "Connect to <ssid>" — so runtime menu mutations (the hotspot row's Enable/Disable flip, a moved Wi-Fi connection) are always current. Ranking is per-token: label prefix < label substring < menu+label substring < subsequence; top 5 render as `Menu ▸ Label` rows. Unlike the Dash's real-focus tiles, focus stays in the input over a virtual selection (`aria-activedescendant` on `role=option` rows; arrows wrap, Tab is parked, Esc clears-then-closes). Enter/click closes *first* and then executes (via `dispatchAction` or a delegated `.click()`) so a dialog the action opens records the pre-HUD element as its focus-restore opener. Open/close/reduce-motion mirror dash.ts exactly; the HUD and the Dash are mutually exclusive (each one's tap detector treats the other's visible overlay as blocking, alongside the lock screen and open dialogs). Session-only; no persistence.
- `assets/js/notify.ts` — NotifyOSD, the passive notification daemon. Two slots like the real one: `notifyValue()` is the synchronous icon + value-bar bubble (volume-style; updates in place and re-arms its 2s timer), `notify()` is the queued text bubble (icon + summary + body, 5s or the caller's 1–20s clamp; an identical summary+body renews the on-screen bubble instead of stacking — "replace" semantics that also fold the stop+start double-emit of a mid-playback track switch into one bubble). The host is `pointer-events:none` so bubbles never take input; a document-mousemove hit-test (attached only while a bubble is up) applies `.is-veiled`, notify-osd's look-through fade. Icons resolve by key from the SSR'd `<template data-notify-icons>` (cloned per bubble, so icon.html's namespaced SVG ids stay unique), with freedesktop aliases (`dialog-information`, `audio-volume-high`, ...) mapped in `ICON_ALIASES`. `initNotify` also listens for the `"up:notify"` window event — the shell bundle's bridge (see Cross-bundle contracts). Bubble producers: top-panel.ts (volume scroll wheel, Wi-Fi connect, hotspot toggle, now-playing) and the terminal's `notify-send`. Session-only; reveal/dismiss honor reduce-motion via the lock.ts fade pattern.
- `assets/js/drag.ts` — `installTitlebarDrag(el, opts)` shared by page-window, trash, and the studio. `spring: true` reproduces the page-window rubber-band; `spring: false` (trash, studio) freezes the chrome at release. Optional `yMin` clamps the final viewport-y, optional `gate` predicate suppresses drag based on outer state (maximized, transitioning). Returns a `DragHandle` (`dispose`/`getOffset`/`setOffset`) exposing the translate3d offset that *is* the window's position — `resize.ts` moves the origin through it so drag and resize never disagree.
- `assets/js/resize.ts` — `installResize(el, opts)` adds eight invisible edge/corner hit zones to a window chrome (trash + studio) for mouse drag-to-resize. Size is applied as inline `width`/`height` clamped to `minW`/`minH` (plus a `yMin` viewport-top clamp on the north edge); north/west resizes derive the origin shift from the clamped size and write it through the shared `DragHandle`. During a gesture the handle's CSS cursor is locked on `body.up-resizing`; an optional `gate` suppresses resize while maximized and `onStart` lets the caller tear down anchored popovers. Pointer-events based (mouse and touch, with wider coarse-pointer hit zones from main.scss) and session-only, matching `drag.ts`.
- `assets/js/focus.ts` — tiny pub/sub for which overlay window (trash or studio) currently has focus. A single `focusedWin` slot models Unity's focus rules: focusing one overlay implicitly unfocuses the other, and the page window is focused exactly when no overlay is (`getOverlayFocused`/`clearOverlayFocus` are what `page-window.ts` consumes; `set/getTrashFocused` and `set/getStudioFocused` are the per-window pairs). `page-window.ts`, `trash.ts`, `daw.ts`, and `top-panel.ts` all subscribe so only one window/title looks focused at a time. Both overlay windows toggle `is-focused` on their *stage* as well as their chrome — the shared `.up-window-stage.is-focused{z-index:35}` raise is what lets the focused overlay paint above the other when they overlap (both stages idle at `z-index:30`).
- `assets/js/page-window.ts` — wires the page window's titlebar buttons (close/min/max), drag, and launcher-tile state. Communicates outward via the `WINDOW_STATE_EVENT` custom event on `window`.
- `assets/js/top-panel.ts` — enhances `_partials/top-panel.html`. Toggles the SSR `[data-dropdown-for]` siblings via the `hidden` attribute, ticks the clock every 30 s, rebuilds `[data-calendar]` on each clock open, runs the volume slider, dispatches `[data-action]` clicks (`nav:<key>`, `dlg:<key>`, `reload`, `fullscreen`, `vol-toggle`, `vol-play`, `daw:open`), keeps its play glyph in sync with the Studio transport via `audio.onChange`, and owns the panel's keyboard layer: triggers are real `<button>`s whose `aria-expanded` it syncs, keyboard opens focus the first dropdown item, Down/Up rove the dropdown's focusables (wrapping), Left/Right switch adjacent visible triggers (suppressed on inputs so the volume slider keeps its arrows), and Escape closes and refocuses the trigger. `dispatchAction` is exported (module-level, no `initTopPanel` state) so the Dash's app tiles run the identical `dlg:*` flows.
- `assets/js/daw.ts` — the Studio window, a period Linux-DAW pastiche (LMMS-flavored: green LCDs, rotary knobs, dark steel) over the `audio.ts` engine, opened from the volume dropdown's "Open in Studio…" row (`daw:open`) or `openStudio()`. Owns the same open/minimize/close state machine + launcher-tile cycle as `trash.ts`, but its launcher tile (`[data-launcher="studio"]`, the piano icon) is a *running-app* tile: SSR'd `hidden`, revealed only while the window is open or minimized. Its `loadSurface()` (re)builds the whole instrument surface client-side for the active playlist entry — keyed on the track index so the `audio.onChange` subscription rebuilds exactly when the selection changes (toolbar prev/next + TRK LCD here, or the panel's next button), with stale-await guards for switches mid-fetch: track strips derived per mixer-strip key (`audio.noteStripKey` — per MIDI channel, except a single-channel song splits into its bass/lead voices; lowest-average-pitch melodic strip reads "Bass", highest "Lead", channel 9 "Drums") with color chip, instrument button (a popover picker over `audio.PATCHES`, mounted inside `.up-daw-body` so the `--daw-*` vars cascade; drums get a blank spacer; selection auditions the new voice at the track's average pitch), mute/solo, and a mini volume knob over the live strip; a synth rack (a nine-voice global selector with a 16x16 glyph per voice — single-cycle waveforms for the shapes, pictograms for the rest (keyboard/bell/plectrum/cloud, and stacked dual waves for Auto's split); the same `PATCH_GLYPHS` set draws the strip buttons and popover items — + attack/release/octave/detune/vibrato), an FX section (cutoff/drive/crush/echo/reverb/width knobs + the echo-sync division buttons), and a groove section (swing/humanize/velocity) all driving `setParam`; a drag-spinbox BPM LCD (double-click restores the file tempo). Rack sections collapse Qt-groupbox-style from their title buttons (`[data-daw-collapse]` → `.is-collapsed`), and the rack scrolls as the fallback, so the full option set fits any window size. The piano roll is one viewport-sized canvas under a transparent scrolling overlay (`[data-daw-scroller]` holds a sized spacer; the canvas redraws from `scrollLeft/Top`, so content size is unbounded without a giant bitmap): black-key rows shaded, bar/beat grid, per-track note colors, a 3-row kick/snare/hat drum lane, sticky key column + bar ruler, Unity-orange playhead. Interactions: click empty grid to audition the pitch (or drum), drag a note vertically to transpose it — the note object is the engine's own, so the edit is audible on the scheduler's next pass — right-click a note to toggle its `dead` flag (the scheduler skips it; the roll keeps a ghost so it can be restored), click or scrub the bar ruler to `seek` (snapped to the sixteenth grid; works paused, where the dimmed playhead marks the cue point), hover paints note info into the status bar, follow-mode jump-scrolls the playhead back into view (hand-scrolling drops follow until re-armed), zoom buttons re-anchor on the viewport center. The titlebar's maximize bead (and double-click) toggles `is-maximized` on the stage — CSS anchors the chrome to the desktop between launcher and panel and neutralizes the drag transform, so restore returns the window to where it was dragged; drags are gated while maximized, mirroring page-window.ts. The rAF loop runs only while the window is visible and repaints only on playback or a dirty flag. Knobs are generic (`makeKnob`: 270° sweep, linear or log, drag/wheel/arrow keys/double-click-reset, `--rot`/`--arc` custom properties drive the CSS pointer + conic value arc). Session-only like everything else: knob values, note edits, and window state reset on reload.
- `assets/js/trash.ts` — owns the trash window's open/minimize/close state machine, launcher-tile cycle, focus sync, and titlebar drag via `drag.ts`. Exports `openTrash()` (mirroring daw.ts's `openStudio`: a module-level opener over the `initTrash` closure that opens or re-focuses, never minimizes) for the Dash's Trash tile. The file grid runs the shared desktop gesture engine (`desktop-select.ts` + `projects-desktop.ts`) with Nautilus trash semantics: double-click opens a "can't open, restore first" dialog whose Restore removes the tile; right-click offers Restore / Delete from Trash (a confirm dialog), applied to the whole selection when invoked inside one; empty space offers Select All / Clean Up Icons. Restore and Delete share one removal flow — tiles animate out via `removeTiles` (honoring reduce-motion) and the footer count tracks both removals and multi-selection ("N items selected"). "Empty Trash" confirms via `uiDialog`, animates the whole list out, then swaps to the empty state and disables the button; removing the last tile individually lands in the same state. All of it is session-only — files return on reload.
- `assets/js/types.ts` — shared types for the modules above and a `declare global { interface Window {...} }` block typing the runtime surface assigned to `window` (`UP_SITE`, `UP_PAGE_WINDOW_STATE`, `uiDialog`).
- `assets/js/shell/` — the home page's interactive xterm.js terminal, bundled from `shell/index.ts` into its own IIFE (`js/shell.js`), loaded only on `.IsHome` (see baseof.html). A renderer-agnostic shell core behind a thin xterm adapter:
  - `terminal.ts` is the sole xterm binding (`TerminalIO` interface + `XtermTerminal`); every other module imports it as a *type only*, so the core stays xterm-free and can run headless.
  - `readline.ts` is the renderer-agnostic line editor: history (seeded + persisted via `onHistoryChange`), tab completion, control-char sanitizing, an emacs keymap (Ctrl-A/E/W/U/K/Y, Alt-B/F/D, Ctrl-arrows, Ctrl-D as delete-forward / EOF), and a Ctrl-R reverse-incremental-search sub-mode. It owns only the line buffer + kill ring; it has no VFS/shell knowledge.
  - `parse.ts` turns a line into statements (`;`/`&&`/`||`) of pipelines (`|`) with a `redirs: Redirect[]` array per command. It resolves quotes/escapes/`~` at parse time but leaves everything runtime-dependent as unresolved `Word` parts: `$VAR`/`${VAR}` (`param`), `${VAR:-w}`/`${#VAR}`/`${VAR#pat}`-style ops (`paramExpr` with a re-tokenized operand `Word`), `$(...)`/backticks (`cmdsub`, holding a recursively-parsed inner program), and `$(( ))` (`arith`, raw text). Each expansion part records whether it was inside double quotes (gates word splitting), and a word sets `hasUnquotedGlob` when it consumed an unquoted literal `*`/`?`/`[`. The tokenizer also recognizes redirection operators (`2>`, `2>>`, `&>`, `&>>`, `2>&1`, `1>&2`, `>&2`, bare `<` input redirection, plus an fd prefix on `>`). `#` starts a comment.
  - `env.ts` is the variable store + expansion source (`Env`): regular/exported vars plus the special params `$?`, `$$`, `$RANDOM`; `isSet` distinguishes unset from null (backing `${VAR-w}` vs `${VAR:-w}`), and `snapshot`/`restore` give command substitution an isolated subshell.
  - `arith.ts` is `evalArith(expr, lookup)` — a recursive-descent integer evaluator for `$(( ))` over bash's operator set/precedence; bare identifiers resolve through `lookup` and are themselves evaluated recursively. The bitwise/shift operators are 32-bit (JS operator semantics), a documented divergence from bash's 64-bit width.
  - `shell.ts` holds the registry, prompt, and the executor. Parameter expansion is **field-based**: `expandFields(word, expander)` concatenates parts and applies IFS word splitting to unquoted expansion results (quoted parts/literals are not split; a bare unquoted empty expansion yields zero fields, a quoted `""` yields one); `expandNoSplit` backs assignment RHS and redirect targets. The `Expander` interface (implemented by `Shell`) supplies `lookup`/`isSet`/`assign`/`runSub`/`arith`/`error`; `runSub` runs `$(...)` through the same shell into a `CaptureSink`, snapshotting cwd+env so mutations don't leak (but `$?` is left as the sub's last status, per bash) and stripping all trailing newlines. After field expansion, words flagged `hasUnquotedGlob` are run through `vfs.glob` (matches replace the field; no match keeps the literal). The pipeline runner computes per-command stdout/stderr sinks from `redirs`, processing them **left-to-right** so `> f 2>&1` and `2>&1 > f` diverge (a dup aliases whatever the target fd points at *at that moment*): stderr defaults to the shell's stderr sink and is **never** piped to the next stage unless an explicit `2>&1`; `2>/dev/null` discards; a real `>`/`>>` target points the fd at a `FileSink` (buffers writes, commits via `vfs.writeFile` at flush time — so a bare `> dir` still surfaces `Is a directory`, and `> f 2>&1` writes once via identity dedupe); `< file` reads a file's lines into stdin (last `<` wins, overriding any upstream pipe). `ShellOptions.stderr` overrides the diagnostics sink (production renders to the terminal; tests capture it). `runLine(line)` executes one line without prompt noise. `CommandContext.requestExit()` (used by `exit`) sets a flag `onLine` consumes after the line finishes: a host-supplied `ShellOptions.onExit` runs instead of the next prompt (headless/test shells pass none and keep prompting; `runSub` saves/restores the flag so `$(exit)` exits only the subshell). `CommandContext` carries `stdin`, `env`, `aliases`, `isTTY` (false when piped/redirected), and `err`/`errln` (the stderr channel); `Command.run` returns the exit status.
  - `ansi.ts` has truecolor/escape helpers, the One Dark palette, and `stripAnsi` (used by the capture sink).
  - `banner.ts` builds the ANSI neofetch banner from the JSON data island.
  - `vfs.ts` is the renderer-agnostic virtual filesystem — a node tree built from `ShellData` (the Hugo-emitted `posts` and `pages` lists drive `~/posts/*` and the top-level `*.md`, so site content is not hardcoded), with path-resolution (`resolvePath`/`lookup`/`displayPath`), `ls`-formatting, tab-completion helpers, and `glob(cwd, pattern)`. `globToRegExp(pat, {leadingDot})` (and its unanchored `globToRegExpBody`) compile a glob to a RegExp and are shared with shell.ts's `${VAR#pat}` operators — the leading-dot rule is opt-in (filename globbing passes it, parameter-expansion patterns don't). The tree includes a small FHS skeleton (`/bin` with `bash`/`sh`, `/usr/bin`, `/usr/local/bin`, `/tmp`) so the paths the shell advertises actually resolve; `installBinary(name)` drops an executable stub under `/usr/bin`, and `resolveCommand(name, cwd, path)` is the PATH search that `which`/`type`/`test -x` **and command execution** share — so command introspection, dispatch, and the filesystem never disagree (delete `/usr/bin/ls`, or wipe the tree with `rm -rf --no-preserve-root /`, and `ls` becomes "command not found"; shell builtins and hidden eggs, which ship no stub, keep working). The tree is **writable for the session**: a `Vfs` write API (`writeFile`/`mkdir`/`removePath`/`copy`/`move`/`touch`) backs `>`/`>>` redirections and the file-mutation commands, each returning a bash-style failure reason (e.g. `"Is a directory"`) or `undefined`. Writes are in-memory only — a reload restarts from the seeded tree (unlike persisted history). Determinism is preserved: every written node's `mtime` is the module-level `SESSION_MTIME` constant (never a real `Date` passed in from a command) and its `size` is a pure function of its content, so the golden `ls`/glob tests stay stable. `splitLines` (shared with the pipeline capture) normalizes a written buffer into stored lines. Keep it DOM-free; seed sizes/modes/mtimes stay static.
  - `commands/nav.ts` is the lone `window.location` wrapper so the VFS stays DOM-free; `commands/*.ts` are grouped `Command`s (`fs` = ls/cd/pwd/cat/open, `meta`, `eggs`, `text` = grep/head/tail/wc/sort/cut/tr/uniq/rev/tac/nl/seq/tee/true/false, `fsmod` = mkdir/rmdir/rm/touch/cp/mv (file mutators over the VFS write API), `path` = basename/dirname/realpath, `find` = find/tree/du/stat/df/file, `sysinfo` = id/groups/uname/hostname/arch/cal, `pager` = less/more (cat-like), `notify` = notify-send (the desktop-notification bridge; see Cross-bundle contracts), `builtins` = alias/unalias/export/env/set/unset/which/type/man, `posix` = `:`/`test`/`[`/`printf`). `text.ts` exports `inputLines`/`splitFlags` for reuse by the other filter/FS modules. `commands/all.ts` exports `ALL_COMMANDS`/`registerAll(shell)` — the single registration list consumed by both `index.ts` and the testkit, so new commands are tested automatically (add a `commands/*.ts` and append it there). A command exposes optional `usage`/`details` for `man`, an optional `complete()` for tab completion, and routes errors through `ctx.errln`; honor `ctx.isTTY` when output format differs for a pipe (e.g. `ls` prints one-per-line when piped). A command marks itself `builtin: true` to model a bash shell builtin (`cd`/`pwd`/`echo`/`printf`/`test`/`[`/`:`/`true`/`false`/`alias`/`unalias`/`export`/`set`/`unset`/`type`/`history`/`help`/`exit`) — `type` reports those as "shell builtin" and no `/usr/bin` stub is installed; every other (non-hidden) command is treated as an external program and `Shell.register` installs a `/usr/bin/<name>` stub for it, so `which` finds it on PATH. Keep the flag honest when adding a command, or `which`/`type`/`ls /usr/bin` drift apart.
  - The xterm deps (`@xterm/xterm`, `@xterm/addon-fit`, `@xterm/addon-web-links`) live in the parent site's `package.json`; esbuild resolves them from `node_modules`. Because the core is xterm-free, it runs headless: `testkit.ts` (type-checked by `tsconfig.test.json`, never bundled — only `index.ts` is an entrypoint — and not a `*.test.ts` so Vitest skips it) provides a `CaptureTerminal`, a deterministic `TEST_DATA` fixture, `makeShell()` (one persistent shell with captured stdout/stderr/status), and `runBash`/`expectMatchesBash` — a differential harness that runs the same program through our shell and real bash and asserts they agree. The `*.test.ts` suites (run via `npm test`, Vitest) cover parsing, expansion, arithmetic, globbing, the VFS, command formatting, and the bash-conformance table.
- `assets/icons/` — every static icon lives here, split into `launcher/` (full-tile launcher artwork, gradient-heavy), `flat/` (larger flat-color illustrations like the wallpaper mark, trash-empty drawing, and empty-pane file/folder shapes), and `glyphs/` (small monochrome UI icons — titlebar dots, sidebar pills, panel indicators, pathbar arrows, stat icons, folder, language-symbol defs). Templates inline a `.svg` file by calling `{{ partial "icon.html" "<subdir>/<name>" }}`; the partial reads the file through Hugo's asset pipeline and emits its body as `safeHTML`. Capturing the call (`{{ $x := partial "icon.html" "glyphs/sidebar-all" }}`) preserves the safeHTML type, which is how sidebar dict-string icons are built.

## Cross-bundle contracts

The shell is a separate IIFE bundle and cannot import symbols from `app.ts`'s bundle at runtime. `terminal.ts` re-fits xterm on the page-window maximize/restore event by listening for the **literal string** `"up:page-window-state"` — this must stay in sync with `WINDOW_STATE_EVENT` in `page-window.ts` (same rename-risk class as the DOM contracts above; importing `page-window.ts` would inline its side-effects into the shell bundle, so the string is duplicated by design).

The notification bridge runs the other way over the same pattern: the shell's `notify-send` (`shell/commands/notify.ts`) dispatches a window `CustomEvent` with the **literal string** `"up:notify"` (detail `{summary, body?, icon?, timeoutMs?}`), which `notify.ts`'s `initNotify` listener turns into a bubble — keep the string in sync with `NOTIFY_EVENT` in `notify.ts`. The dispatch sits behind a `typeof window` guard (the nav.ts isolation rule) so the command runs — and is tested — under headless Node, where there is no daemon to reach.

`desktop-select.ts` and `projects-desktop.ts` are imported by both the `app.ts` bundle (via `trash.ts`) and the `projects.ts` bundle, so esbuild duplicates them into each and two engine instances coexist on `/projects/`. That is safe because every piece of gesture/selection state lives in the `installDesktop`/`createSelection` closures and the engine's document-level listeners guard on it — never add module-level mutable state to either file.

## Site-provided globals

`baseof.html` injects `window.UP_SITE = { handle, github, repo, rss, nav }` from `Site.Params.author.name` (via `_partials/ui/author-handle.html`), `Site.Params.social[name=github]`, `Site.Params.repoUrl` (the source-repo link the "View source" dialog renders), the RSS output format, and the `_partials/site-pages.html` page registry (`nav` maps each page key to its URL; top-panel.ts resolves `nav:<key>` actions through it) before the JS bundle loads. Components that need site identity (e.g. the top-panel session menu) read from `window.UP_SITE` rather than re-deriving from the DOM. The `Window` augmentation lives in `assets/js/types.ts`; keep it in sync if you add new globals.

## Editing notes

- `hugo.IsProduction` controls esbuild minification of the app, blog, projects, and shell bundles; the CSS pipeline is `css.Sass | resources.Minify | resources.Fingerprint`, with `outputStyle: expanded` passed to Dart Sass so Hugo's minifier remains the size-reducing step. SRI integrity attributes are emitted for every fingerprinted asset.
- The shell bundle (`js/shell/index.ts` → `js/shell.js`) is gated on `.IsHome` in `baseof.html`, kept off `app.ts`, and `defer`red — xterm core is large, so this keeps it off every other page and off the critical path. Adding a terminal command = add a `commands/*.ts` module and append it to `ALL_COMMANDS` in `commands/all.ts` (consumed by both `index.ts` and the testkit).
- `main.scss` inlines the structural CSS from `@xterm/xterm`'s `css/xterm.css` (the `.up-shell` block, after the neofetch section) because there is no `[module]` block in `hugo.toml` to mount `node_modules` into Hugo Pipes. The inlined block is pinned to a specific xterm version in a comment — bump it in lockstep when upgrading `@xterm/xterm`. Terminal colors come from the JS `theme` (`terminal.ts`), not CSS; only layout rules are inlined, with `.xterm-viewport` background forced transparent so the `.up-neofetch` HUD blur shows through.
- Fonts are fully self-hosted: the seven Ubuntu / Ubuntu Mono faces live in the parent site's `static/fonts/` as latin + latin-ext woff2 subsets, declared via `@font-face` at the top of `main.scss` with the same unicode-ranges Google Fonts served; `head.html` preloads Ubuntu 400 everywhere and Ubuntu Mono 400 on the home page.
- New dropdown content goes in `_partials/top-panel.html` as a `[data-dropdown-for=<key>]` sibling of the matching trigger; new actionable rows just need `data-action`. Add a case to the `async` `dispatchAction()` in `top-panel.ts` if the action key is new: a purely-static joke goes in the `DLG_PRESETS` map; anything that reads the environment or holds state gets its own `await` branch (see `dlg:time`, `dlg:power`, `dlg:subscribe`, `dlg:hotspot`, `dlg:lock`, `dlg:prefs`).
